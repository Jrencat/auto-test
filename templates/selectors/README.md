# 选择器适配器（UI 库可插拔附录）

引擎主规则（`rules/script-rule.md`）**不假设任何 UI 组件库**。写页面级断言时，规则只引用下表的
**语义角色**；角色 → 真实 CSS 选择器的映射，由本目录下**对应 UI 库的适配器**提供。

换 UI 库 = 换一个适配器文件，主规则一行不动。

## 一、语义角色表（主规则只认这些名字）

| 角色 | 含义 | 典型用途 |
|------|------|---------|
| `APP_ROOT` | 应用挂载根节点 | 判断未白屏/未崩溃 |
| `TABLE_ROOT` | 表格根容器 | 判断表格已渲染 |
| `TABLE_HEADER_CELL` | 表头单元格**文本**节点 | 列集合断言（聚合比对） |
| `TABLE_ROW` | 表体数据行 | 行数/空态断言 |
| `COMBO_INPUT` | 下拉 / 自动完成组件的**可输入框** | 输入业务标识触发查询 |
| `PLAIN_INPUT(placeholder)` | 普通文本输入框 | 按 placeholder 精确定位 |
| `FORM_ITEM_LABEL(text)` | 表单项标签 | 判断表单项显隐（变体矩阵） |
| `MESSAGE_TOAST` | 全局轻提示 | 读取操作结果文案 |
| `FORM_ERROR` | 表单校验错误文案 | 读取字段级校验提示 |

> 角色不够用时**在适配器里自行扩展**，并在本表追加一行说明——不要把库特定选择器写回主规则。

## 二、可用适配器

| 文件 | 适用 UI 库 | 来源 |
|------|-----------|------|
| `antd-vue-aggrid.md` | Ant Design Vue + ag-Grid | 实测验证 |

## 三、选用方式

1. 绑定 `project.json` 的 `ui.selectorProfile` 指定适配器文件名（相对本目录）：
   ```json
   "ui": { "selectorProfile": "antd-vue-aggrid.md" }
   ```
2. 留空或文件不存在 → 主规则按 **§四 自行探测流程** 现场推导选择器，并把结论沉淀成新适配器。

## 四、没有现成适配器时（自行探测流程）

1. 打开目标页面，用 Playwright `page.locator(...)` 或浏览器 devtools 定位角色对应的真实节点。
2. **优先选语义化/稳定的选择器**：`data-test` 属性 > 组件库根类名 > 结构类名；
   **避免**依赖列序、nth-child、随机 hash 类名。
3. 验证：每个角色至少跑通一次 `toBeVisible()`，确认不是"选择器找不到元素"被误判为功能缺陷。
4. 把验证过的映射写成新的 `<库名>.md` 适配器（照抄 `antd-vue-aggrid.md` 的结构），
   并在上表 §二 登记，供后续项目复用。

## 五、编写适配器的强制要求

- **每行必须实测过**，禁止凭组件库文档臆测——未验证的选择器会把脚本问题伪装成产品缺陷。
- 必须写「常见错误」列：说明**为什么**直觉写法会落空（这是适配器最有价值的部分）。
- 库特有的多步动作序列（如下拉需 `click → fill → 等候选 → Enter`）一并收录，主规则只写"按适配器的动作序列"。
